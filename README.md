This repository contains a formal model of the EVM in Lean 4.
It is an EVM-focused port of Nethermind's
[EVMYulLean](https://github.com/NethermindEth/EVMYulLean) to a newer version of
Lean, with the Yul model removed.
The aim is to simplify proof development over the model.

Everything here is work in progress and is subject to change therefore.

The changes in this repository are intended to ease proof development over the
EVM model, with some tradeoffs against executable performance. They do not
relax the behavioral compatibility target. The conformance suite has changed,
and the model is now tested against the EEST:
[execution-spec-tests](https://github.com/ethereum/execution-specs).

For a summary of the main differences from Nethermind's upstream project, see
[nethermind-changes.md](nethermind-changes.md).

# Project structure

## Forks
The semantics is parametric in the execution-layer fork, from Cancun to Osaka:
```
Ethereum/Fork.lean
```

## EVM
The model of the EVM state `EVM.State`:
```
Ethereum/State.lean
```

The semantic function `step`:
```
Ethereum/Semantics.lean
```

## Cryptography

Ethereum's Keccak-256 is implemented in
[`Ethereum/SpongeHash/Keccak256.lean`](Ethereum/SpongeHash/Keccak256.lean).

`hash` computes on `Nat` lanes so that the kernel evaluates concrete hashes
quickly, as `decide +kernel` proofs about function selectors and storage slots
require. `referenceHash` computes the same function on `UInt64` lanes;
`hash_eq_referenceHash` proves them equal and, as a `csimp` lemma, makes
compiled code run `referenceHash`.

The other cryptographic primitives are in [`Ethereum/Crypto`](Ethereum/Crypto):

- SHA-256, RIPEMD-160 and the BLAKE2 compression function `F`;
- ECDSA public-key recovery on secp256k1 (`ECRECOVER`, transaction senders
  and EIP-7702 authorities) and secp256r1 signature verification (EIP-7951,
  Osaka);
- the alt_bn128 operations (`BN_ADD`, `BN_MUL`, `SNARKV`, with the optimal ate
  pairing);
- the BLS12-381 operations (EIP-2537, Prague), including the RFC 9380 maps to
  `G₁` and `G₂`, and the KZG point evaluation (EIP-4844).

They share prime and quadratic extension fields (`Field.lean`), Jacobian
arithmetic on short Weierstrass curves (`Curve.lean`) and the `𝔽ₚ¹²` tower and
Miller loop of both pairings (`Pairing.lean`). Merkle Patricia trie roots are
computed in [`Ethereum/State/TrieRoot.lean`](Ethereum/State/TrieRoot.lean).

The output sizes of the precompiles are proved: each primitive comes with a
theorem that a successful result has the size prescribed for it (for example
`Ethereum.Crypto.SHA256.hash_size` and
`Ethereum.Crypto.BLS12_381.precompile_size`), which the return-data bounds of
`Ethereum/Theory/ReturnDataBound.lean` use. Nothing proves that the primitives
compute the correct cryptographic values; the conformance tests and the
cryptography tests below are the behavioral checks for them.

## Cryptography tests
The primitives are also tested on their own, against vectors from
independent reference implementations (hashlib, pycryptodome, libsecp256k1
through coincurve, OpenSSL through cryptography, py_ecc) and the `TrieTests` of
[ethereum/tests](https://github.com/ethereum/tests), together with algebraic checks such as the
bilinearity of the pairings:
```
lake exe crypto-tests
```
The vectors live in `CryptoTests/Vectors.lean` and are generated by
`scripts/gen-crypto-vectors.py`, using the Python packages of
`requirements.txt`; it downloads the trie tests at a pinned commit. The
generation is deterministic, so running
`python3 scripts/gen-crypto-vectors.py > CryptoTests/Vectors.lean` again
reproduces the file.

## Conformance testing
The model is tested against the blockchain fixtures of
[execution-spec-tests](https://github.com/ethereum/execution-specs), pinned to
release `tests@v21.0.2`. The test running infrastructure can be found in:
```
Conform/
```
Run the conformance tests with:
```
lake test 2> out_discard.txt
```
We recommend redirecting `stderr` into a file to not pollute the output.

The first run downloads the pinned fixtures.
The pins and the fetching are in `lakefile.lean`.

This runs every fixture network from Cancun on.

`lake test -- --help` lists conformance parameters.
